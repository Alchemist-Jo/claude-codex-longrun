## Objective

After this brief, `evalkit run --resume <run-dir>` continues an interrupted run from the first shard without a result file, and produces the same results file as an uninterrupted run on the same inputs.

## Context

- `src/evalkit/runner.py`: `run_shards` writes one result file per shard; `--resume` currently restarts from shard 0.
- Ruling of 2026-10-12 on a03: resumption is generic in the runner; adapters keep dataset-specific recovery.
- Fixture: `tests/fixtures/tiny/` has 4 shards and runs in under 10 seconds.

## Changes

1. In `run_shards`, skip shards whose result file exists and is complete, and start from the first shard without one.
2. Treat a result file without its end marker as incomplete and rerun that shard.
3. Add tests for an interruption after shard 2, and for a truncated result file in shard 1.
