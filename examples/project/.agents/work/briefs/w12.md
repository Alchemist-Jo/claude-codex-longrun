## Objective

After this brief, `evalkit run --resume <run-dir>` continues an interrupted run from the first shard without a complete result file, and produces the same results file as an uninterrupted run on the same inputs.

## Context

- `src/evalkit/runner.py`: `run_shards` writes one result file per shard; `--resume` currently restarts from shard 0.
- Note `.agents/notes/proposed/architecture/2026-10-12-generic-shard-resumption.md`: resumption is generic in the runner; adapters keep dataset-specific recovery. The close-out of this brief moves it to `implemented/`.
- Fixture: `tests/fixtures/tiny/` has 4 shards and runs in under 10 seconds.

## Changes

1. In `run_shards`, skip shards whose result file exists and is complete, and start from the first shard without one.
2. Treat a result file without its end marker as incomplete and rerun that shard.
3. Add tests for an interruption after shard 2, and for a truncated result file in shard 1.

## Out of scope

- The command-line interface in `cli.py`.
- Parallel shard execution.

## Acceptance

1. `pytest tests/test_runner.py -k resume` passes and selects the two new tests.

3. A result file truncated before `#end` is rerun: the truncated-shard test fails when the end-marker check is removed.
